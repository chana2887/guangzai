# 光崽 × ESP32｜软硬件联调交接

适用版本：罗小黑 V2.0，软件基线 `5894957`。第一次联调用一台 Windows 电脑、一块 ESP32 和一根 USB 数据线即可开始。第一轮要看到的效果是：从装置左边靠近，控制台亮起左侧感应灯，空闲的小黑朝观众左边转头。第二轮再用三个实体键选择「玩耍 → 一起玩」，重启后小黑还记得这次互动。

## 谁接什么

| 部件 | 职责 | 本轮交付 |
| --- | --- | --- |
| ESP32 · 硬件组 | 读两路红外、消抖、控制舵机，通过 USB 串口上报 | 现有示例已包含红外和转台。硬件组提供实板型号、接线表、可烧录固件和原始串口样例；下一步增加三键采集 |
| Windows 电脑 · 软件组 | Python 接收串口、驱动宠物状态、用 SQLite 保存记忆。浏览器播放白底动画和气泡 | 现有版本可直接接红外；下一步把串口按键接到现有菜单，再验证记忆和重连 |
| 屏幕与反射装置 · 硬件组、动画组 | 屏幕接电脑的视频输出；换树莓派后按实际屏幕选 HDMI 或 DSI。浏览器打开净投影页 | 从观众位置对齐左右，检查白底、镜像、完整角色和气泡。现有待机、左右转头和玩耍片段可以直接测试 |

**数据怎么走**　红外 → ESP32 → USB → 主机 Python → 浏览器动画。舵机由 ESP32 在板端驱动。菜单、成长、动画文件和存档都在主机上。需要自由问答时，在主机控制台用键盘输入，Python 联网调用 DeepSeek，再把回答显示到投影气泡。首次联调可全程离线，ESP32 只需连 USB。[对话配置与存档说明](../README.md#接入-api-对话)

## 第一轮｜接上现有固件，看到小黑转头

1. **硬件组核对板子和引脚。** 仓库示例针对经典 **ESP32 Dev Module**、Arduino-ESP32 **3.x**。左红外数字输出 DO 接 GPIO32，右 DO 接 GPIO33，固件默认低电平有效。舵机信号接 GPIO18。先核对模块 DO 与 3.3 V GPIO 的电平兼容性；舵机按铭牌单独供电，与 ESP32 共地。若实板型号不同，先按该板引脚图确认可用脚、调整固件并记录实际映射。第一轮可以先只观察串口和画面，接舵机时先空载回中。[固件入口](../firmware/guangzai_ir/guangzai_ir.ino) · [Espressif 安装与板型资料](https://docs.espressif.com/projects/arduino-esp32/en/latest/getting_started.html)
2. **烧录并确认板子会说话。** 在 Arduino IDE 打开上述 `.ino`，保留同目录的 `gesture.h`，选实际板型、端口并上传。串口监视器选 **115200**。双侧留空约一秒，应反复看到 `GZ1,0,N,C`。从观众左侧遮挡一次，看序号和方向变化，再移开手。记下 COM 号，**关闭串口监视器**，让光崽服务接管端口。
3. **软件组启动主机。** 从仓库根目录运行以下 PowerShell 命令，按列出的实际端口替换 `COM3`。独立联调存档可以反复使用，便于检查重启后的记忆。

   ```powershell
   python -m pip install pyserial
   python -m serial.tools.list_ports -v
   python server.py --serial COM3 --data-dir data/esp32-trial --open
   ```

4. **两组一起对照实物。** 控制台应显示「ESP32 已连接」。打开同一主机的[白底投影页](http://127.0.0.1:8780/?projection=1)，将窗口移到装置屏幕。让小黑处于清醒待机、菜单收起状态，分别遮挡左右，每次之间双侧留空约一秒。对照三件事：控制台哪盏灯亮、转台实际朝哪边、小黑在最终反射画面里看向哪边。若只有反射画面相反，调控制台「画面校准」的水平镜像；若只有转台相反，空载核对舵机左右预设。目标字段只代表板子下达的目标位，实际到位要看实物。

### 当前串口格式（已实现）

USB 串口 **115200、8N1**，一行一帧 ASCII，以 LF 结尾，兼容 CRLF。板子约每 200 ms 发一次心跳，检测区变化或接受新手势时也发。字段顺序是 `GZ1,手势序号,检测区,舵机目标`。

| 依次操作 | 可见的原始帧 | 主机应看到什么 |
| --- | --- | --- |
| 上电，左右留空 | `GZ1,0,N,C` | 已连接，目标居中 |
| 单独遮左 | `GZ1,1,L,L` | 接受一次左手势；持续遮挡序号不再增加 |
| 移开手 | `GZ1,1,N,L` | 感应灯灭，转台保持上次目标 |
| 同时遮两侧 | `GZ1,1,B,L` | 两灯亮，无新增手势 |
| 再次留空约一秒，单独遮右 | `GZ1,2,R,R` | 接受一次右手势 |

序号为无符号 32 位整数，按已接受的手势递增。相同序号的心跳只更新状态；连接或重连后的首帧用作基线。固件当前消抖 80 ms，转动稳定期 650 ms，双侧清空至少 140 ms 后才可重新触发。硬件组升级感应方式时，可以继续输出相同的检测区和已接受事件，保留主机接口。[板端判定](../firmware/guangzai_ir/gesture.h) · [主机串口接收](../hardware.py)

## 第二轮｜把三个实体键接到已有菜单（待开发）

现在可以用电脑的 **←、→、Enter** 验证完整菜单。现有固件只上报红外，主机串口解析器也只识别 `GZ1`。建议实体键复用同一根 USB 线，增加独立的按键帧，两组可按下表并行开发。

| 交接项 | 硬件组 | 软件组 |
| --- | --- | --- |
| 接线与键义 | 选三个适用于实板的空闲输入脚，回填左／中／右 GPIO、按下有效电平。消抖后一次按下发一次，长按到松手只发一次 | 将左、中、右映射为 `left`、`center`、`right`。无菜单时任一键打开菜单，已有菜单时左右切换、中键确认 |
| 建议新增帧 | 每次开机先发一次 `GZK1,0,BOOT`。随后每次有效按下只发一行 `GZK1,<按键序号>,<L/C/R>`，例如 `GZK1,1,L`。按键序号从 1 递增，独立于手势序号 | 在串口接收层分流两种帧，按顺序逐个消费按键，丢弃重复序号。新建连接或收到 BOOT 时清空按键去重记录，让首个新按键生效。原有红外心跳继续按原协议处理 |
| 菜单与记忆 | 提供一段「左、中、右、长按、快速连按」的原始串口记录 | 复用 `Companion.button(key, revision)`，保留现有菜单版本校验，过期确认不重放。由主机统一应用一次按键，控制台和投影读取同一状态。继续沿用动作完成时写入玩耍记忆的逻辑 |

以上 `GZK1` 是本次交接建议，须由两端实现后才能验收。现有键盘路径可作为对照。[菜单处理](../companion.py) · [现有键盘入口](../public/js/app.js)

## 台架验收单

| 操作 | 通过标准 |
| --- | --- |
| 当前版本，分别遮左、遮右、持续单侧、同时遮两侧 | 空闲小黑对有效单侧手势各转一次头；持续遮挡不连续触发；双侧亮灯并保持原目标。转台和反射画面方向由两组现场确认 |
| 拔掉 USB，等待 2 秒，再插回同一端口 | 控制台离线，主机继续运行。恢复「ESP32 已连接」后无旧动作重放，下一次有效手势正常。若系统更换 COM 号，用新端口重启服务 |
| 加入实体键后，从空闲打开菜单，连续右按两次，再长按一次中键 | 前两次右按各移动一项，长按只确认一次；控制台与投影选项一致。拔插或复位后再按一下，新按键仍有效 |
| 用三键选「玩耍 → 一起玩」，等动画播完；用相同存档目录重启 | 记忆簿里本轮只有一条完成记录，再开玩耍菜单会提起上次玩过。另选一次「晚点吧」，完成数应保持原值 |
| 换到最终屏幕，在观众位置观察 | 左右正确，耳尖、脚、尾巴和气泡均在画面内，带载转动时屏幕线有余量 |

**常见卡点**　显示「模拟输入」时检查启动命令是否带 `--serial`；显示「串口暂不可用」时检查 COM 号、USB 数据线和串口监视器占用。端口可打开却一直「等待 ESP32」时，退出服务，在监视器检查是否收到完整的 `GZ1` 行；若出现 `ERR:PWM`，该固件会暂停上报，先检查板型和 PWM 配置。感应灯变化但角色没转头时，先看手势序号是否递增，再回到清醒待机、收起菜单复测。

**换树莓派时**　先在电脑跑通同一块板，再把仓库放到有桌面和 Chromium 的树莓派。安装 `python3-serial`，用 `ls -l /dev/serial/by-id/` 找到板子，将实际完整路径填入 `GUANGZAI_SERIAL=/dev/serial/by-id/实际设备名 bash kiosk.sh`。默认打开净投影，按 G 可回控制台检查连接。若要延续电脑上的养成，先停止两端服务，再将联调存档目录复制到树莓派，并用 `GUANGZAI_DATA_DIR` 指向它。[部署和校准细节](联调.md)

**联调结束请回传**　板型和板卡包版本、实际 GPIO 接线表、固件提交号、主机系统和串口号、一次左右感应及三键的原始帧，以及一段能同时看到手、转台和投影的短视频。逐项标记「通过／待修／未测」，并写下出现偏差的那一步。目前实体接线、转台到位和反射效果均待样机验证。
