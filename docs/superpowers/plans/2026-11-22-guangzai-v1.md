# 光崽第一版软件实施计划

> 依据[已确认的体验与验收标准](../specs/2026-11-22-guangzai-v1-design.md)。每个任务有可单独核对的交付结果。

**目标**是用两个红外、三个按钮和角色气泡，让光崽在装置上完成互动、记忆、个性化待机、成长与装饰搭配。

**实现途径**沿用 Python 本地服务、SQLite、HTML/CSS/JavaScript、树莓派 Chromium 和 ESP32 USB 串口。由本地服务统一维护光崽状态和当前选择，网页控制台与净屏投影消费同一状态。设备缺席时使用临时企鹅、模拟红外和模拟按键。

## GitHub 资源筛查与复用决定

这一轮核对了上游仓库、与光崽有关的源码文件及许可证。以下决定用于第一版 V1–V4，第三方库和显示工具仍要在实际设备上验证。

### 自由聊天记忆的后续候选

**SQLite FTS5、sqlite-vec、Mem0、LangMem** 留待自由聊天需要搜索大量旧记录时再比较。当前的玩耍回忆和称呼读取走 SQLite 结构化查询，离线也能验收。Windows 本机用临时内存库验证过，FTS5 的 trigram 全文查询可命中三字「一起玩」，两字「玩了」未命中。日后如果使用 FTS5，需要为短中文查询保留查找路径。向量方案还需要评估嵌入模型和树莓派运行成本。 [SQLite FTS5](https://www.sqlite.org/fts5.html#the_trigram_tokenizer) · [sqlite-vec](https://github.com/asg017/sqlite-vec) · [Mem0 配置](https://docs.mem0.ai/open-source/configuration) · [LangMem](https://github.com/langchain-ai/langmem)

## 软件组实施顺序

### 1. 跑通三个按键和投影气泡（V1）

预计涉及 `hardware.py`、`server.py`、`companion.py`、`public/index.html`、`public/js/app.js`、`public/style.css`，验证放在 `tests/test_hardware.py` 和 `tests/test_companion.py`。

- [x] 控制台提供左、中、右三个模拟按键。控制台和投影页也支持键盘。第一下只打开菜单，左右轮转「摸摸头」「投喂」「玩耍」「返回」，中键确认。选「玩耍」后可以回应「一起玩」或「晚点吧」。
- [x] 选项随每次操作更新编号，确认或闲置 30 秒后失效。已用自动化测试验证同一选项被两个窗口同时确认时只执行一次，旧编号无法触发动作。
- [x] 用临时企鹅在 Edge 同时打开控制台和黑底投影，验证选项、摸头、投喂、玩耍和短句同步。气泡和角色共用画面校准，在两个窗口验证了镜像同步。在 1280×800、800×480 和 390×844 的默认校准画面中，菜单和企鹅之间均有留白。
- [ ] 硬件组交付串口样本后，把实体键接入模拟按键使用的同一个菜单处理入口。用实物左右红外和三个键核对 V1，从正常观看位置检查文字、选项和正式素材的留白。

### 2. 让交互产生可回忆的经历（V2）

预计涉及 `companion.py`、`notebook.py`、`conversation.py` 和 `tests/test_companion.py`。保留现有 SQLite 存档格式与读取路径，增加记忆所需的信息。

- [ ] 从「一起玩／晚点吧」做第一个对话。确认「一起玩」时开始玩耍，规定动作窗口结束后写一条独立的完成记录。按对话编号和互动编号去重。同一次启动中的刷新或重复请求不重复写入。重启时能恢复已经完成的记录，未完成的旧会话按结束处理。
- [ ] 从最近一次真实玩耍完成记录生成再次相遇的邀请。没有记录时使用「要不要一起玩？」。调度任务决定何时可以提起，使用本地短句就能完整跑通。选「晚点吧」时播放对应回应，保持原有玩耍记录和长期玩耍偏好。
- [ ] 沿用键盘输入与显式记忆流程。新称呼替换用于打招呼的旧称呼。增加装置侧问候读取称呼的验证。用现有记忆簿核对互动记录，运行重启、双窗口、重复确认和拒绝场景。

### 3. 做出能看出来的待机与性格（V3）

预计涉及 `pet.py`、`companion.py`、`public/js/display.js`、`public/animations/manifest.json` 和 `tests/test_companion.py`。

- [ ] 保留长期性格与当前饱腹、精神、陪伴等状态。把现有长期互动分数用到候选动作和邀请上，常摸头提高凑近权重，常玩耍提高蹦跳权重。当前困倦、睡眠和自习影响可选动作。
- [ ] 分别调度短小待机动作和低频主动搭话。当前明确互动优先，红外触发后的转头先于可选邀请，小动作可以让位。对话超时后收起，等待下一次调度，避免连续弹同一个问题。睡眠与自习采用自己的动作节奏。
- [ ] 用现有可控制时间的测试夹具验证动作、邀请和超时。为现场演示提供可重复的节奏与起点，按 V3 在一分钟内看小动作、三分钟内看主动搭话。用相同成长阶段、临时状态和可重复的随机条件检验两种性格的动作倾向。日常调度单独校准。

### 4. 接入成长解锁与自由装饰（V4）

预计涉及 `pet.py`、`notebook.py`、`companion.py`、`public/js/app.js`、`public/js/display.js`、`public/animations/manifest.json` 和 `tests/test_companion.py`。

- [ ] 沿用现有成长阶段，定义首批阶段奖励。用「转头后挥手」验证新动作，用「光崽主动邀我自习」验证新活动。原有自习入口可以继续由我发起，成长奖励增加光崽主动提出这件事的能力。跨阶段时只登记一次解锁事件。
- [ ] 首批准备一个书房小场景和一件围巾装饰。菜单提供「换场景」「换装」和返回入口，只显示可设置的已解锁项目，两个选项分别保存，各自可回默认。加载旧存档时默认使用初始搭配，并根据已有成长阶段判断奖励资格。
- [ ] 把场景道具作为独立透明图层，服装按动画组的交付约定使用同构图的穿戴版本。开发期间用占位场景和装饰验证选择及存档。如果某个素材缺失，画面回退到现有基础动作，界面保留可辨认的当前选项。
- [ ] 用成长前后的演示存档测试锁定、解锁和独立搭配。检查刷新和重启后的成长、已解锁项及搭配，随后用正式素材在反射屏上核对 V4。

### 5. 完成实物联调与版本验收（V1–V4）

记录位置为 `docs/联调.md`。现有联调文档描述原型，接入新按键协议时补上实际固件版本和接线。

- [ ] 软件端跑 `python -m unittest discover -s tests -v`。Windows 上先用模拟按键和红外从头走完 V1–V4 的软件部分，验证两个窗口、重启、关掉联网模型后的体验。
- [ ] 在树莓派和 ESP32 实物上记录接线、端口、固件与按键库版本、按键映射与反射校准。先按 VEEB 流程播放黑底定向样片，再打开光崽的 Chromium 投影页。复测单次按键、长按不重复、红外与按键同时输入、USB 拔插重连。
- [ ] 从实物的正常观看位置验证气泡可读、装饰不会遮挡选项、动作衔接清楚。按 V1–V4 逐条记载通过项、缺失的真机或正式素材项和复测结果。

## 动画组需要交付

| 批次 | 交付物 | 对接要求 |
| --- | --- | --- |
| 第一批 | 循环待机，左看、右看各一个短片，摸头、投喂、玩耍的短片 | 优先完成，可直接替换临时企鹅验证 V1、V2。提供每段的用途及建议循环或单次播放方式。 |
| 第二批 | 安静的小动作、亲人时凑近、爱玩时蹦跳、转头后挥手、可以陪自习的动作 | 短动作从接近待机的姿态开始，结束能接回待机。凑近和蹦跳的差异要能从实物观看距离看出来。 |
| 装饰 | 书房道具透明图和一款围巾。围巾提供与第一版验收动作同构图的穿戴片段，或与角色运动同步的透明图层。交付时列出覆盖哪些片段 | 书房元素分开放置，角色组提供位置参考。第一轮先核验围巾在待机、转头、玩耍和挥手上的跟随效果。 |

角色片段沿用现有 MP4 或 WebM 清单接法。首轮可用静音 H.264 MP4、24 或 30 fps。统一黑底、分辨率、镜头、角色缩放与站位，为转头、动作和角色旁气泡留出余量。文件名用可区分方向和动作的英文名。先交一段待机和一段左看样片，软件组和硬件组一起在反射屏核验画幅、亮度、镜像和留白，再补齐整批片段。

## 硬件组需要交付

| 交付物 | 对接要求 |
| --- | --- |
| 两个红外和三个实体按键 | 标出真实左、右感应区与三个键的位置。提供 ESP32 实际板型、引脚、电平与消抖设置。确认左、右键切换，中键确认，每次按下只发一次事件。 |
| 可联调的 ESP32 固件与串口记录 | 保留现有 `GZ1` 红外与舵机状态帧。拟新增 `GZB,<序号>,<L/C/R>` 独立按键事件，115200、8N1，LF 结尾。上报的是消抖后按下瞬间，按住和释放不重复上报。提供左／中／右各按一次、长按、红外同时触发和重连的串口样本。写明复位时编号如何重置，让软件可区分新一轮输入。 |
| 树莓派、显示屏、转台和可组装的反射样机 | 提供系统、屏幕接口、方向、实际分辨率和有效反射范围。记录舵机左右方向、转动稳定状态和实际观看位置。给软件与动画组一轮能测试字大小、道具留白和左右镜像的样机时间。 |

串口对象沿用硬件组可独立控制舵机、软件组根据事件决定角色动作的分工。协议名和帧格式是本计划的联调约定，正式接线和转动范围以实物记录为准。

## Git 协作

- `main` 保存能运行的版本。开发按上述任务开短期分支，分别提交，再用带验收编号与结果的 Pull Request 合入。
- 缺陷挂到对应验收编号。正式素材随组间交付核对，项目仓库追踪清单与可分发素材。工作中使用的个人存档和模型密钥沿用现有忽略规则。
- 组装后的实物完整通过 V1–V4 后，再打 `v0.1.0` 标签。当场看不到的事项保留具体复测条件。
